# D1 — Model the data

**20 minutes.**

## Where we are

Same pipeline. Same €0 delivery from 2026-03-04. No checks yet.

You are going to describe the datasets and press go.

## What this mission is about

Your Airflow DAG answered one question: *what work must run, and in what order?*

Dagster asks a different one: *what datasets exist, what are they made of, and
when is one valid?*

Three assets from a template is not hard, and it is not supposed to be.
**The observation at the end is the deliverable, not the code.**

## Your task

1. **Define three assets** in `dagster/src/rootsmarkt/defs/assets.py`:

   ```
   raw_delivery  ->  clean_sales  ->  daily_revenue
   ```

   Declare each edge with `@asset(deps=[upstream])`. The TODO block in that file
   tells you what each asset should do and which sealed function to call.

2. **Attach metadata to each materialization.** At minimum: the row count on
   `clean_sales`, and `total_revenue_eur` on `daily_revenue`.

   Return `MaterializeResult(metadata={...})`, not a bare value.

3. **Materialize all three** for business date 2026-03-04.

4. **Open the asset catalog and write down what it tells you about the result.**

## What success looks like

Three assets materialize successfully. **Nothing fails.** If you think you broke
something, you did not — success is the expected outcome here.

The catalog shows a green lineage graph, and `daily_revenue`'s latest
materialization carries `total_revenue_eur: 0.00` as visible metadata **on a
successful run**.

That is the point. The failure is legible in the catalog without anyone having
written a single check.

```
roots verify d1
```

reports `asset_graph_defined` and `assets_materialized`.

## One thing that will trip you up

`@asset def clean_sales(raw_delivery)` — taking the upstream asset as a function
parameter — is the idiomatic Dagster form **when assets return values**. These
assets return `MaterializeResult` and hand data over on disk and in Postgres, so
there is no stored output to load and no IO manager to load it with.

Use `deps=[...]`.

## Where the layers are

- **Orchestration:** the asset boundaries and their dependency edges — deciding
  *what counts as a dataset*.
- **Processing:** the sealed modules, unchanged from this morning.
- **Boundary:** which values are worth attaching as metadata. That choice
  determines what this system can tell you in six months.
